# 트렌드 분석 실데이터 연결 (2026-09-16)

## 1. 바뀐 점 요약

| 구분 | 이전 | 현재 |
|---|---|---|
| backend 코드 | feedit 자체 사본(구 스키마) | `SKN31-FINAL-4Team/backend` 최신본으로 동기화 |
| DB 접속 | SSM 터널 `127.0.0.1:5433` | RDS 직접 연결 (`.env` 의 `DB_HOST`=RDS 주소, `DB_PORT`=5432) |
| 트렌드 탭 수치 | 온도·긍부정 일부만 실값, 나머지는 씨드 난수·목업 | 6개 탭 모두 API 실값, 값이 없으면 '측정 불가' |

## 2. 탭별 데이터 출처

| 탭 | 주소 | RDS 표 |
|---|---|---|
| 언급량·온도 | `/api/trend?term=` | `analysis.term_metric_daily` (trend_temperature · level · momentum · 플랫폼별 행) |
| 연관어 | `/api/assoc?term=` | `analysis.term_assoc_daily` (lift · PMI · 순위) + `analysis.text_term_mention` 근거 문장 |
| 긍부정 | `/api/trend?term=` | `term_metric_daily` 의 positive/negative_rate · 반응 유형 건수 · purchase_intent_index |
| 할인률 변화 | `/api/discount?style=&kind=&brand=&item=&term=` | `snapshot.product_source_snapshot` |
| 리세일 시세 지수 | `/api/resale?…` | `snapshot.resale_snapshot` (+ 정가: market_metrics.regular_price 또는 판매 스냅샷) |
| 수명주기 | `/api/lifecycle?…` | `term_metric_daily` 의 level·ma28·momentum (판정 규칙은 응답의 `rule`) |

DB 에 칸이 없는 값(배송일·반품률·쿠폰·남은 착용 시즌 예측 등)은 화면에서 제거하고, 실제로 있는 값(평점·리뷰 수·재고 상태·주별 온도)으로 바꿨다.

## 3. 로컬 실행

```bash
# 백엔드 (RDS 직접, 루트 .env 의 API_PORT 사용)
cd backend && python manage.py runserver 8001
curl http://127.0.0.1:8001/api/health        # 표별 행 수·스키마 어긋남 확인

# 프론트
cd frontend && npm run dev                     # /api → 루트 .env 의 API_PORT 프록시
node tests/_integration_live.mjs               # 6개 탭을 실제로 그려 보는 확인
```

※ `docker/compose.yml` 은 더 이상 SSM 터널을 기본으로 띄우지 않고, `migrate` 도 자동 실행하지 않는다
(스키마의 주인은 SKN31-FINAL-4Team/backend). 터널이 필요하면 `--profile tunnel`.

※ 새 의존성: `pgvector`(DictionaryTerm.embedding), `djangorestframework`.

## 4. 배포(Vercel)

- `api/[kind].js` 가 `/api/discount` · `/api/resale` · `/api/lifecycle` 을 함수 하나로 받아 Django 로 넘긴다 (Hobby 요금제 함수 12개 제한).
- 필요 환경변수: `BACKEND_API_URL`, `BACKEND_API_TOKEN` (= 서버 `.env` 의 `FEEDIT_API_TOKEN`).
- EC2 의 Django 도 이 backend 로 다시 배포해야 새 주소가 열린다.
