# FEEDIT 관리자 대시보드 개편 계획

## 원칙

- 현재의 아이보리 배경, 흑백 중심 색상, 둥근 카드와 타이포그래피는 유지한다.
- 장식보다 운영자가 빠르게 상태를 파악하고 원인을 추적하는 것을 우선한다.
- 원본 데이터 화면은 큰 디자인 개편 대상에서 제외하고, 빈 필터·명칭·조회 오류만 정리한다.
- 개인정보는 관리자 화면에도 기본 노출하지 않는다.
- 운영 DB를 바꾸는 기능과 조회 기능을 명확히 분리한다.

## 전수조사 결과

### 공통 UI

- 약 900~1100px 폭에서 상단 메뉴가 글자 단위로 줄바꿈된다.
- 일부 넓은 표가 콘텐츠 영역을 밀어 페이지 전체 가로 스크롤을 만든다.
- 표가 43개인데 `nz-table`, `adm-table`, `dTable`, 페이지 전용 표가 혼재한다.
- 템플릿 인라인 스타일이 269곳이며 수집 타깃 화면에만 156곳이 있다.
- DB 기본키가 굵은 첫 열로 반복 노출돼 실제 업무 정보보다 시각적 우선순위가 높다.
- 이미지 로딩 실패 시 빈 흰 칸으로 남아 URL 부재와 이미지 오류를 구분할 수 없다.
- 한글 화면에 영문 제목·상태·버튼이 섞여 있고 같은 상태의 색상과 문구가 화면마다 다르다.
- 빈 결과가 실제 데이터 없음인지, 필터 불일치인지, 적재 전인지 구분되지 않는 화면이 있다.

### 데이터와 운영

- Source 코드의 대소문자가 혼재한다(`ABLY`, `YOUTUBE`, `musinsa` 등).
- 네이버 블로그와 네이버 검색은 서로 다른 데이터 축인데 일부 화면에서는 이름만 보고 중복처럼 보인다.
- 검색 Source는 `RawDocument`가 아니라 검색 지표 테이블에 적재되므로 원본 데이터 필터에 빈 항목으로 노출하면 안 된다.
- 트렌드 화면 일부가 삭제된 지표 필드를 참조하고 있었다.
- 시스템 상태의 서비스 연결 검사가 실제 Docker/운영 환경 변수와 다르면 거짓 장애가 표시될 수 있다.
- `views.py`가 수천 줄 단위로 커져 화면별 스키마 변경을 추적하기 어렵다.

### 현재 데이터 규모

- 사용자 47명, 사용자 이벤트 736건
- 살!말? 게시글 46건, 댓글 135건, 투표 227건
- 챗봇 세션 79건, 메시지 90건
- 사용자 취향 109건
- 유튜브 댓글 38,296건, 무신사 상품 리뷰 15,007건, 에이블리 상품 리뷰 2,666건

## 구현 순서

### 1차 — 화면 기반 안정화

- 상단 메뉴를 줄바꿈 없는 반응형 구조로 변경한다.
- 페이지 전체 가로 스크롤을 제거하고 넓은 표 내부에서만 스크롤되게 한다.
- 카드, 필터, 표, 상태 배지, 페이지네이션, 빈 상태, 모달을 공통 컴포넌트로 통합한다.
- 번호 열은 `DB ID`로 명확히 표시하고 작고 옅게 처리한다. 목록 순번이 필요하면 페이지 기준 순번을 별도로 표시한다.
- 이미지 셀은 `이미지`, `URL 없음`, `로드 실패`를 구분하고 원본 URL 열기/복사를 제공한다.
- 상태와 버튼 문구를 한글 중심으로 통일하고 기술 코드는 보조 텍스트로 둔다.
- 수집 타깃 화면의 인라인 스타일을 제거하고 공통 CSS로 옮긴다.

완료 기준:

- 1280px 이상에서 모든 핵심 열과 액션을 바로 사용할 수 있다.
- 900~1279px에서 글자가 세로로 쪼개지지 않고 페이지 전체 가로 스크롤이 없다.
- 이미지 오류가 빈 칸으로 보이지 않는다.

### 2차 — 정규화 파이프라인 한눈에 보기

다음 흐름을 하나의 클릭 가능한 파이프라인 맵으로 표시한다.

`CrawlRun → RawDocument → ProductSource/ContentItem → TextDocument → TextTermMention → TermMetricDaily/TermAssocDaily`

검색 지표는 별도 가지로 표시한다.

`NAVER_SEARCH/GOOGLE_SEARCH → TermSearchMetricMonthly → 검색·연관 지표`

각 단계에는 다음을 표시한다.

- 전체 건수, 오늘/최근 24시간 증가량
- 마지막 적재 시각과 경과 시간
- 대기/성공/실패 건수와 전환율
- 이전 단계 대비 누락량
- 클릭 시 해당 필터가 적용된 상세 화면으로 이동

### 3차 — 서비스 사용자와 행동 로그

사용자 목록에서 허용하는 정보:

- 내부 사용자 ID
- 서비스에 공개되는 닉네임
- 가입일, 마지막 활동일
- 검색/조회/저장/투표/댓글/챗봇 이용 건수
- 취향 등록 수와 XP/레벨 같은 운영 지표

기본적으로 숨기는 정보:

- 이메일, 로그인 아이디, 생년, 성별, 체형
- 인증 토큰, 세션, IP, User-Agent
- 채팅 원문과 자유 입력 메타데이터

행동 로그는 이벤트 유형, 시각, 대상 종류/내부 ID만 노출하고 `metadata`는 허용된 키만 표시한다. 사용자별 상세 화면에서는 활동 타임라인과 집계만 제공한다.

### 4차 — 살!말? 운영 화면

- 게시글: 이미지, 제목, 공개 닉네임, 상태, 투표 수, 댓글 수, 신고 수, 생성일
- 댓글: 게시글 문맥, 공개 닉네임, 의견, 내용, 숨김 상태, 신고 수
- 신고 화면에서 게시글/댓글 원문으로 바로 이동
- 1차는 읽기와 필터 중심으로 만들고, 운영 액션은 숨김/복구 같은 소프트 처리만 제공
- 모든 운영 액션은 수행자, 시각, 대상, 변경 전후를 감사 로그에 기록

### 5차 — 데이터베이스 도구

#### 테이블 현황

- 스키마별 그룹과 검색
- 추정 행 수, 전체 용량/인덱스 용량, 마지막 분석 시각
- 업무 테이블은 모델별 최신 적재 시각과 상태 분포 추가
- 큰 테이블에 기본 `COUNT(*)`를 실행하지 않고 PostgreSQL 통계를 사용

#### ERD

- Django 모델 메타데이터와 실제 FK를 기반으로 생성
- `collection`, `dictionary`, `commerce`, `content`, `analysis`, `app` 스키마별 색상 구분
- 테이블/컬럼 검색, 스키마 접기, 관계선 강조, SVG 내보내기
- 개인정보 컬럼은 이름만 보이거나 기본 숨김 처리

#### 읽기 전용 SQL 콘솔

- 별도 read-only DB 계정/연결을 사용
- `SELECT`, `WITH ... SELECT`, `EXPLAIN`만 허용
- PostgreSQL read-only transaction, statement timeout, 최대 200행, 단일 문장 제한
- `auth`와 개인정보 테이블은 차단하거나 마스킹된 운영 View만 허용
- 결과 다운로드는 기본 비활성화하고 필요 시 별도 권한으로 분리
- 실행자, 시각, 소요 시간, 성공 여부, 쿼리 해시를 감사 로그에 기록

### 6차 — 시스템 로그와 마무리

- 수집/Celery/애플리케이션 오류를 같은 필터 체계로 조회
- 환경별 서비스 주소를 사용해 거짓 장애 표시 제거
- 요청/작업 ID로 수집 실행부터 분석 작업까지 추적
- 핵심 목록 화면, 권한, 개인정보 마스킹, 읽기 전용 SQL에 회귀 테스트 추가
- 1280px/1440px 화면 시각 회귀 점검 후 배포

## 바로 반영한 항목

- 삭제된 트렌드 필드 참조를 현재 지표 스키마로 교체
- 전체 지표와 플랫폼별 지표가 섞이지 않도록 전체 집계만 사용
- 원본 데이터 필터에서 실제 문서가 없는 네이버/검색 Source 제거
- Source별 원본 문서 건수 표시
- SKN31 작업본의 텍스트 문서 화면을 현재 스키마에 맞게 이식
- 유튜브 댓글·자막, 무신사/지그재그/에이블리 상품 리뷰, 네이버 본문 메뉴 추가
- 텍스트 화면에 썸네일, 원문 링크, 분석 상태, 현재 `TextTermMention` 결과 표시
- `analysis_metadata.candidates`를 전처리 후보로 분리 표시하고 검증 키워드와 혼동되지 않게 개선
- 이미지 로드 실패와 URL 부재를 구분하고 실패 시 원본 URL로 이동할 수 있게 개선
- 922px 화면에서 상단 메뉴·서브 메뉴가 세로로 쪼개지지 않는 반응형 레이아웃 적용
- Siri 느낌의 상태 오브젝트와 60초 캐시를 적용한 클릭형 파이프라인 현황 추가
- 개인정보를 제외한 사용자 현황·활동 로그와 살!말? 게시글·댓글 운영 화면 추가
- Django 모델 FK 기반 ERD 탐색, PostgreSQL 통계 기반 테이블 현황 추가
- 단일 SELECT, 3초, 200행, 민감 테이블·위험 함수 차단을 적용한 읽기 전용 SQL 화면 추가
- Docker의 실제 `redis` 서비스 주소를 상태 검사와 Celery 설정에 일치시켜 거짓 장애 제거
- N+1 회귀 방지를 위한 목록 쿼리 상한 테스트와 읽기 전용 SQL 보안 테스트 추가
